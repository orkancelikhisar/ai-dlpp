Conclusion

Q1 — partly. A 2 B model checks every message inside a second at no cost, and the shippable pipeline stops two leak-bearing messages in three while interrupting one clean prompt in four. That protection is the regex tier's: no in-browser model beats a trivial rule at the policy's judgment call. Structured identifiers yes, a client relationship in prose no.

Q2 — yes, on accuracy. One hosted model of five, DeepSeek, clears the floor in every pass and catches five leaks in six at lower over-blocking; the two with published sizes never clear it. Latency matches the browser's best, at cents per thousand messages. Hosted inference is forbidden by the cloud boundary, so this describes what a local server would deliver.

Q3 — yes, and it is the biggest change. Dropping generated text, and letting code propose spans while a judgment model only keeps or rejects them, clears the floor by a wider margin than any language model here, never flags a clean message, and moves 0.029 between passes where the language models moved up to 0.344. Fastest arm in the study, and hosted, so it inherits Q2's boundary.

Verdict: ship the in-browser tier for what it does well — real-time identifier catching at 1 s and $0 — and put the semantic judgment on a server you control. The design that transfers is the shape rather than the vendor: code proposes the candidates, a small judgment model keeps or rejects them, and the threshold stays yours to set.

Bounds: one policy, one predicate, 19 gold positives (one item moves recall by 0.053); the judgment arm's span recall is capped by the candidates code proposes; the corpus generator gives every positive a capitalised organisation name, which flatters both the floor and the separation; the reasoning result is one pass with 31% of rows lost to rate limiting.
